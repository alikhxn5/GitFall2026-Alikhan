(c) What command(s) could you use to obtain the list of files that
    were in a repository on a specific date?
----------------------------------------------------------------

Command: git ls-tree -r --name-only $(git rev-list -n 1 --before="2020-06-01" HEAD)

It's two commands stacked. The inner one finds the most recent commit made
before that date. The outer one lists every file in the tree at that
commit, recursing into folders.

Nothing comes back for 06/01/2020. That's not an error, the repository
didn't exist yet. The oldest commit is "starter files" from Sep 10 2024, so
there's nothing before that date to list.

Also worth saying: ls-tree only knows about tracked files. Anything
untracked or ignored was never in a commit, so no command can reconstruct
it for a past date.

(d) How many times was each of the files inside the src folder
    modified?
----------------------------------------------------------------

Command: git log --format=format: --name-only -- src | sort | uniq -c | sort -rn

Result:
   1 src/file.java

src has one file in it and it changed once, in the "Files added" commit.

The pipeline lists the filenames touched by every commit involving src,
sorts them so duplicates end up next to each other, counts each group with
uniq -c, then sorts by that count.

It counts by path though, so if a file had been renamed at some point its
history would split into two separate counts. --follow fixes that, but it
only takes one path at a time.

(f) What is the difference between git log and git status?
----------------------------------------------------------------

They report different things at different points in time.

git log is committed history. What got recorded, by who, when, with what
message. All of it is already saved and none of it is going to change.

git status is right now. Which files differ between my folder, the staging
area, and the last commit, and which branch I'm on. None of it is permanent
yet.

Step 17 made this obvious. I'd staged book.txt and then appended to it
again, and git status listed the same file twice, once under "Changes to be
committed" and once under "Changes not staged for commit". That isn't a
bug. The staging area was holding the version from when I ran git add and
my folder was holding the newer one. Two real versions sitting in two
different places. git log had nothing to say about any of it, because none
of it had been committed.

Log looks backward at what's permanent. Status looks at what's still in
progress.

----------------------------------------------------------------
(g) What does the command shortlog do?
----------------------------------------------------------------

Command: git shortlog

shortlog summarizes the log by author instead of listing every commit on
its own. By default it groups commits under each person's name with their
subject lines underneath, which is what my step 5 output shows, all twelve
of them under Esteban Parra with the count in brackets.

Adding -s drops the subject lines and just gives a count per author, and -n
sorts by that count. Those two pretty much always get used together, as
git shortlog -sn.

It was originally built for writing release announcements, so the question
it answers is who contributed and how much.

(i) What command would you use to list the commits in which the
    file "Main.java" was part of the committed files, including
    renames and the diffs of each commit?
----------------------------------------------------------------

Command: git log --follow -p -- Main.java

Same as (h) with two flags added.

--follow keeps tracing the file back through renames, so if Main.java used
to be called something else those older commits show up too. Git can do
this because it tracks content rather than filenames, and works out renames
by how similar the content is between commits.

-p prints the actual diff each commit introduced instead of just the
metadata, so I can see line by line what changed each time.

Nothing comes back.

--grep searches commit messages, both the subject and the body. It's case

Not the same as git grep, which searches inside the tracked files

----------------------------------------------------------------
(k) What command would you use to see the commits made by a
    specific person?
----------------------------------------------------------------

Command: git log --author="Esteban"

This returns all twelve of Dr. Parra's commits, since he's the only person
who committed to the original repository.

--author matches against the author field as a substring, so a first name,
a last name, or part of an email address all work. It takes a regex too if
I wanted to match a few people at once.

Git keeps author and committer as separate fields. The author is whoever
wrote the change, the committer is whoever applied it. Those are usually
the same person but they split apart when someone applies a patch on your
behalf or when history gets rewritten. --committer searches the other one.
